# Decisions

- D01: Native Swift with AppKit and SwiftUI, packaged through SwiftPM and a shell bundler. The installed command line SDK is sufficient; a full IDE install is unnecessary.
- D02: Target this Apple M5 computer with 16 GiB memory on macOS 27.0.1. Swift 6.4 and the macOS 27 SDK are present. Node, a package manager, speech synthesis, SQLite, and REA CLI are available. No global installation is needed.
- D03: Recognition is interchangeable. Probe system on-device recognition and asset availability before requesting a downloadable decoder. Never silently download a language asset or fall back to network recognition.
- D04: Rules are the default cleanup. Optional local language generation must satisfy a deadline and conservative output validation. A missing model never blocks ordinary rule cleanup.
- D05: Use a project-local signing keychain if available. Do not modify the login keychain. Ad hoc signing is an explicitly documented fallback until a stable identity is created.
- D06: The user's accompanying request authorizes the additional milestones. Record the intermediate checkpoint results, then continue through dictionary, styles, hands-free capture, selected-text editing, and the hub.
- D07: Inspect only the behavioral specification after its creation. A checker alone can consult the analysis directory to detect accidental overlap.
- D08: Prefer one-process native integration. Native audio, pasteboard, global shortcuts, and Accessibility do not need an IPC helper in this app.
- D09: The command line SDK lacks XCTest. Use a compiled standalone Swift verification executable driven by `make test`, rather than installing an IDE or weakening coverage.
- D10: System English speech assets and a local system language model are already installed. Microphone is undetermined; Accessibility and monitoring are not granted. These are manual OS grants, not build blockers.
- D11: This SDK ships SwiftUI declarations that depend on absent macro plugins. Use native AppKit views instead of requiring a full IDE or switching to a web runtime. The user experience and native architecture remain intact.
- D12: Downloaded a checksum-pinned English small-class speech model and a 1.5B four-bit instruction model after authorization. The downloaded decoder reads PCM from standard input; no microphone file is required. System speech reports installed locales but rejects the requested asset state, so the bundled decoder is the initial reliable default.
- D13: Build optional decoder tools in the project directory. License notices accompany bundled executable resources. The application makes no inference-service requests.
- D14: The first downloaded-model speech comparison measured a 0.459 second median including process startup, with approximately 2.1% normalized word error on three synthetic clips. These are not microphone-to-insertion measurements or a full ten-second acceptance claim.
- D15: The four-bit instruction model produced a valid synthetic correction but took 5.389 seconds cold, beyond the allowed editing budget. Keep the LLM disabled; retain the guarded adapter and model for future optimization. Deterministic editing is the shipped default.
- D16: Prefer ordinary paste for selected-text replacements so the target app owns undo. Direct Accessibility writes are not enabled without evidence of reliable undo behavior in that target.
- D17: Support five physical hold keys and release only the recording started by that hold. Repeated key events and tap reconfiguration must not end an unrelated toggle session.
- D18: Classify destination apps locally and preserve editor/terminal syntax by default. Users can disable that behavior. Decode settings with per-field defaults so an upgrade does not discard existing preferences.
- D19: Optional cleanup may adjust punctuation and casing only after deterministic editing. Every content word, number and configured spelling must survive. A deadline race returns the rule result promptly even if an inference task is slow.
- D20: The installed system language model passed the expanded ninety-case suite only after explicit punctuation and content-word fidelity checks. Automatic cleanup uses this on-device adapter behind a versioned, fixture-bound, expiring qualification record and an 800 ms deadline. It remains optional and falls back to deterministic editing.
- D21: The bounded engine comparison measures the bundled GPU and CPU paths, a locally derived compact variant, and both system speech APIs. Asset- or permission-blocked paths are reported as unavailable rather than assigned invented scores. The compact five-bit variant had the same measured word error and lower latency, so it is selected when its pinned checksum verifies.
- D22: App-owned native text controls provide real Unicode paste and undo/redo tests without granting access to other applications. Synthetic-audio pipeline latency is reported separately from live microphone and cross-application acceptance.

- D23: Permission diagnostics must come from the launched GUI process. A child launched by a terminal can inherit a different TCC responsibility context. Only anonymized permission, model and delivery metadata is written; no transcript or audio is part of this diagnostic.
- D24: Resolve a lazily exposed focused editor with a bounded, cancellable retry while microphone capture starts. Require the original app/window, then recheck field identity, cursor and available text before a paste. Recreated accessibility wrappers can match only with stable geometry and identity/text evidence.
- D25: Read only the latest microphone RMS from a lock-protected slot. A visible-only display timer applies logarithmic normalization and attack/release interpolation; audio buffers never enqueue individual UI updates. Respect Reduce Motion and stop the timer on dismissal.
- D26: Use an original midnight/violet/mint native interface with sidebar navigation, wave artwork, typography, hover feedback and brief transitions. Generate the matching application icon from project-owned drawing code. Preview screenshots use empty content rather than saved transcripts, vocabulary or snippets.

- D27: Plain dictation must work in editors that expose only an opaque group or window. A recording-scoped listen-only event tap tracks focus-changing input as one Boolean, without retaining keys or pointer locations. If Input Monitoring is available, the same known app/window and uninterrupted keyboard focus can authorize ordinary paste without an AX text field. Password/protected input remains blocked, and selected-text rewrites still require a readable selection. Opaque group values are not treated as the destination's text.
- D28: The running GUI process can evaluate delivery readiness on request without posting any input. Delivery diagnostics retain role, app and Boolean evidence only, allowing a failed insertion to be distinguished from a missing permission without exposing a transcript or field value.

- D29: Keydown is the display name, bundle filename, and app executable name. Keep the original bundle ID, signing identity, and application support directory so existing macOS grants and user data carry over. Archive the prior installed bundle when upgrading.
- D30: Use the menu bar app as the opt-in login item. Defer window and audio engine creation until needed. Suspend input and cancel pending work during sleep or an inactive user session, then restore shortcuts once every interruption clears. Scope the user-initiated activity to dictation and allow idle system sleep.
- D31: Recognize hold-to-talk after a short standalone press. Ordinary keyboard chords cancel a pending hold. A Keydown chord interrupts an owned hold before executing its action. Debounce Carbon presses until release and keep queued events tied to their original registration.
