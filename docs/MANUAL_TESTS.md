# Manual acceptance checks

These checks require the signed app's operating-system grants. No permission status is inferred from a unit check.

1. Launch the built app, enable microphone access, enable Accessibility, and refresh the status. Rebuild at the same location and confirm the grants remain associated with its stable signing identity.
2. Open TextEdit, click a new document, and use Control Option Space. Speak, then press the shortcut again. Confirm insertion at the original caret and undo with Command Z.
3. Repeat in Notes, a Safari textarea, a Chrome textarea, Slack, and a code editor. These applications may expose different Accessibility attributes; record results available for explicit copy separately from observed insertion.
4. Put multiple items and custom rich clipboard types on the pasteboard. Dictate and verify byte-identical contents return. During the restore interval, copy new content in another app; verify Keydown leaves the new clipboard owner alone.
5. Change app, field, cursor position, or selection while recognition runs. Verify the result is available through Copy Previous Text and the clipboard does not change automatically. A protected/password field must receive nothing.
6. Cancel during capture and decoding. Start another session immediately. Confirm old work cannot insert text, close the newer indicator, or overwrite the new status.
7. Grant Input Monitoring, enable the globe/function hold shortcut, and set the system globe action to Do Nothing in Keyboard settings. Confirm key release finishes capture and ordinary typing still works.
8. Exercise the indicator on a different Space and over a fullscreen app. It must not become the focused window. Drag it and relaunch to check saved docking.
9. Disable Wi-Fi after model setup. Dictate several utterances and use every local editing feature. Confirm no additional assets are requested.
10. From an installed app, enable Open at Login in Settings. Check the reported state in Keydown and macOS Login Items. On a fresh login, confirm the menu bar icon appears without a window. Open Keydown from its menu, then close the window and confirm the shortcut still works.

11. Try each physical hold-key option. Repeated key-down events must start once and release must end only the recording started by that hold. Disabling or reconfiguring a held trigger must cancel its recording. Ordinary toggle capture must survive an unrelated hold-key release.
12. In Settings, validate local cleanup and enable it only after qualification. Try spoken punctuation, instructions that should be dictated as text, names, numbers, and lists. Confirm that a slow model falls back promptly. Revalidate after OS or fixture changes.
13. Try dictation in a code editor or terminal. Exact syntax should be preserved when the option is on; ordinary prose cleanup should return when it is disabled. Confirm inferred categories and per-app styles suit your use.
14. After several real dictations, inspect this-launch timing in Settings. Record observed microphone-to-insertion latency separately from the app-owned synthetic fixture results.

15. With the Mac unlocked in a disposable profile, run `bash scripts/build_fixture.sh` and grant Accessibility to the separately identified Keydown Fixture app. Run `python3 scripts/cross_app_check.py` to check Unicode paste and native undo/redo against its owned test destinations. The fixture checks its expected target PID and bundle identifier.
16. If a result is available for copy, read the specific reason in the indicator or its history outcome. Test missing Accessibility, a moved caret, a changed field, and a held Control/Option key independently.

17. In a custom editor with no accessible text field, confirm the transcript is available through Copy Previous Text and the clipboard stays unchanged until you choose it. Repeat after changing the cursor or focus.
18. Run `/Applications/Keydown.app/Contents/MacOS/Keydown --diagnostics --check-delivery` with the intended app focused. It asks the existing GUI process to evaluate readiness and prints metadata only; `posted_input` must be false.
19. Put the Mac to sleep or switch macOS users during a disposable dictation. On return, confirm the recording has stopped, the indicator has cleared, and the interrupted text does not paste. Try the toggle and the configured hold shortcut again. Repeat while recognition is in progress and while changing the input device.
20. Set hold-to-talk to Right Option. Try Control Option Space with Right Option pressed first and Control pressed first. Each chord should perform one toggle, even if Space is held until key repeat. Try Control Option R and V with Right Option. Holding Right Option by itself should start capture, and a pause while holding it should leave capture active. Check ordinary Option typing and repeat with Right Control as the hold key.

21. Try a free-form edit against a synthetic selection. Confirm Review Suggested Edit presents a preview and leaves the selection and clipboard alone until you choose Copy Suggested Edit. Verify literal “press enter” remains text and never submits a form.
22. With Never Save selected during a slow synthetic decode, confirm its completion leaves no row or recording. Delete an older entry and check that Paste Previous and the Hub no longer show it. In a short capped session, delay the UI and confirm the stored sample count is bounded.
23. Upgrade a disposable signed build that omits a previous optional resource. Verify the old resource disappears, the designated requirement stays stable, and an invalid staged update leaves the existing app valid.

## Product polish acceptance

Record the candidate's Settings build identifier and active provider for each run. The old installed app is not evidence for newly built source. Use synthetic drafts and do not submit them.

24. On the built-in display, sleep and wake ten times with Codex windowed. For the first and second Right Option recordings after each wake, observe visible Starting → Listening → Processing, the menu-bar recording state, preserved target focus, and release stopping. Expected: 20/20 visible recordings. Include interrupted captures; old work must stay cancelled. Repeat a smaller TextEdit set. Idle wake must not start the microphone.
25. Interrupt a short indicator dismissal with a new session, sleep, or display change. The newer panel must stay opaque and on screen. Test Settings preview/reset with microphone permission denied; it must not request or use the microphone. Repeat with a negative-origin second display, fullscreen, Spaces and a removed display. Drag and relaunch; saved docking remains reachable.
26. Speak quietly, normally, and with clipping; compare recognized text to actual speech. Confirm no-input/device removal cancels promptly, first/last words survive, and holding across silence does not finish early. Test hands-free against real room noise; the local sound classifier needs device/accent/noise qualification; uncertain sound must delay silence completion. Record first-buffer and observed-visibility latency separately.
27. Speak the time correction “five fifteen PM, actually make that five fifty PM”; compare it with “five fifteen PM, not five fifty PM”. Check the recognized and formatted stages separately. Verify literal comma-key/press-enter language, quoted phrases, iPhone/macOS/OAuth, AB-007 versus AB-070, 1,205 versus 12,500, 7.05%, 3.14.2 and both negation polarities. No claim of recognition accuracy is valid without the audio/reference pair.
28. Exercise Dictate prose and Exact text in the same app. In Exact text, “spell A B hyphen zero zero seven” yields AB-007; invalid spelling commands remain literal. Confirm migrated preferences keep previous code preservation. Compare held-out sentences with vocabulary off/on; verify unrelated speech does not acquire hinted names.
29. Start another capture while recognition is busy; the current job must retain its identity/result. Escape then allows a fresh capture. Force a destination change; Copy/Review recovery must work without automatic clipboard modification. Review highlights are advisory, edits have local undo, and Copy copies the currently edited result. Delete/prune a reviewed history entry and confirm the window clears.
30. Open Practice Dictation. Use hold, toggle and Start / stop, then close during processing. Its sessions must leave no history row, audio file, automatic clipboard write or external paste. Its Copy and Add spelling actions require explicit clicks. Test opening ordinary dictation in another app while the practice window remains open; only a focused practice window selects practice routing.
31. Enable VoiceOver and Reduce Motion. Check useful phase announcements, readable static status, accessible recovery controls, and a quiet idle state. Export diagnostics to a new file; inspect for absence of transcript, vocabulary, field contents, clipboard and audio. Inspect only synthetic canaries for this test.

30. In a disposable draft, test space-grouped amounts (including nonbreaking spaces) and compound weekday IDs. Compare recognition with cleanup; ambiguous corrections must remain visible. Confirm ordinary numbers/times/weekdays still correct.
31. Test normal speech, speech immediately at Listening, short/quiet speech, 60 seconds of non-speech noise and speech playback from another device. Uncertain results must open for review without typing, modifying a selection or touching the clipboard. Verify explicit copy, cancellation, retention-off behavior and classifier-unavailable fallback. Test clear silence versus ambiguous background sound during hands-free mode; no energy calibration period should swallow initial speech.

32. Hold dictation through speech followed by a long noisy or silent tail; repeat with leading noise and speech/noise/speech. Results must open for review without automatic insertion or interpreting a selected-text edit. Check a normal utterance with a one-second pause still qualifies on the same device, and that quiet/short utterances remain available to copy. Three-second gap and two-second aggregate pause allowances are conservative policies, not speech-recognition guarantees.
